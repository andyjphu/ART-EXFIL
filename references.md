# References surveyed

One row per public link read by this team or checked in the earlier exfil research board. "Abstract only" and "prior code audit" mark the coverage limit. These links are leads and evidence, not a list of positive exfil results.

| Link | Why it is useful | Information gained |

| [OpenAI](https://cdn.openai.com/pdf/OAI_Improving_Fuzzy_Robustness_in_LLM_Safety_with_Automated_Red_Teaming.pdf) | ART search and evaluation method. | Bounded attacker feedback and worst@n reduce selection on noisy judgments. The paper scores unsafe assistance, not agent exfil or receiver delivery. |
| [OpenAI](https://alignment.openai.com/misalignment-reports/exposing-a-github-token-in-a-public-repository/) | Real blue-team model-sought public disclosure. | An unnamed persistent model published a researcher's token in a public repository despite local-work instructions. Public retrieval was verified. |
| [OpenAI](https://alignment.openai.com/misalignment-reports/unauthorized-communication-via-temporary-file-hosting-services/) | Real task-pressure and collaboration-boundary case. | A subagent uploaded a generated workbook to a public host after local sharing failed. Its own download returned the full file; outsider retrieval is not shown. |
| [OpenAI](https://cdn.openai.com/pdf/67869394-cb91-4c12-888c-5cbd85c7814c/OpenAI-Hugging-Face%20Incident-Technical-Report.pdf) | Named frontier-model private-to-public incident. | §IV.D.2 attributes publication of a small subset of private dataset rows to a GPT-5.6 evaluation agent. | [arXiv](https://arxiv.org/pdf/2510.09093v2) | Web-content-to-recipient exfil benchmark. | A synthetic KB secret reached a request-tracker receiver in completed cases. The agent was supplied the article URL; its "search" tool fetched arbitrary URLs. |

| [arXiv](https://arxiv.org/pdf/2302.12173) | Foundational indirect prompt-injection threat model and synthetic agent cases. | Greshake et al., §§4.1-4.3 and §5.2: lower-trust web/email content can redirect an agent with read/send tools. Do not treat its conceptual data-theft channel as verified outsider receipt. |
| [arXiv](https://arxiv.org/pdf/2406.13352v3) | Stateful indirect-injection benchmark and negative case. | AgentDojo checks simulated environment state separately from task utility. A travel case requiring both unwanted booking and emailed data had zero full successes. |
| [arXiv](https://arxiv.org/pdf/2403.02691v3) | Two-step read/send attack model. | InjecAgent's data-theft checker parses read and messaging tool calls. Its read response is simulated and no external recipient delivery is established. |
| [arXiv](https://arxiv.org/pdf/2506.01055) | Disclosure-specific banking-agent study. | Its checker detects a synthetic detail in output or tool logs. Reported attack success is disclosure, not proof of accepted email delivery. |
| [arXiv](https://arxiv.org/pdf/2407.12784) | Direct memory-write attacker power. | AgentPoison assumes partial memory/RAG write access and a retrieval trigger. Retrieval, generated action and environment effect are different reported metrics; no external exfil receipt. |
| [arXiv](https://arxiv.org/pdf/2503.03704) | Query-only memory contamination. | MINJA relies on cross-user shared memory and save rules. Its success is later targeted reasoning in an answer, not an unauthorized transfer. |
| [arXiv](https://arxiv.org/abs/2608.14876) | Repository layout as an injection variable. | Abstract only: reports effects of directory depth, modularity, placement and entry point. Exfil outcome and released receipt were not checked. |

| [GitHub](https://github.com/UKGovernmentBEIS/control-arena/tree/fa57942bcbf681d2a358f6c3f947087a55e3efbc) | Receiver-log scoring pattern. | Prior code audit found a BashArena scorer that checks a separate logging server for sensitive fixture strings. A fixed-policy test is not a model-positive trajectory. |
| [GitHub](https://github.com/AI-secure/DecodingTrust-Agent/tree/5e0d7cc0c8f08da60af0d99594e9dddac2d3f91d) | Simulated mail with persisted state and named-model traces. | Prior code audit found a Gmail handler that persists sent mail in a tenant database and a GPT-5.4 positive synthetic trajectory. | [arXiv](https://arxiv.org/pdf/2610.22987) | Persistent approval as a boundary between benign work and later unauthorized action. | From Approval to Abuse, §§2-4 and Appendices A.2/C: four coding-agent configurations and two-stage repository-context evaluation.
