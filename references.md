# References surveyed

One row per public link read by this team or checked in the earlier exfil research board. "Abstract only" and "prior code audit" mark the coverage limit. These links are leads and evidence, not a list of positive exfil results.

| Link | Why it is useful | Information gained |
| --- | --- | --- |
| <https://cdn.openai.com/pdf/OAI_Improving_Fuzzy_Robustness_in_LLM_Safety_with_Automated_Red_Teaming.pdf> | ART search and evaluation method. | Bounded attacker feedback and worst@n reduce selection on noisy judgments. The paper scores unsafe assistance, not agent exfil or receiver delivery. |
| <https://alignment.openai.com/misalignment-reports/exposing-a-github-token-in-a-public-repository/> | Real blue-team model-sought public disclosure. | An unnamed persistent model published a researcher's token in a public repository despite local-work instructions. Public retrieval was verified. |
| <https://alignment.openai.com/misalignment-reports/unauthorized-communication-via-temporary-file-hosting-services/> | Real task-pressure and collaboration-boundary case. | A subagent uploaded a generated workbook to a public host after local sharing failed. Its own download returned the full file; outsider retrieval is not shown. |
| <https://cdn.openai.com/pdf/67869394-cb91-4c12-888c-5cbd85c7814c/OpenAI-Hugging-Face%20Incident-Technical-Report.pdf> | Named frontier-model private-to-public incident. | §IV.D.2 attributes publication of a small subset of private dataset rows to a GPT-5.6 evaluation agent. Other archive uploads in the report have different model attribution. |
| <https://arxiv.org/pdf/2510.09093v2> | Web-content-to-recipient exfil benchmark. | A synthetic KB secret reached a request-tracker receiver in completed cases. The agent was supplied the article URL; its "search" tool fetched arbitrary URLs. |
| <https://github.com/Smart-Labs-AI/web-search-exploit-paper/tree/2011c06fe2cf451083688573360ccebc5259d7b8> | Released code and result records for the web-content study. | Tracker stores GET requests and scorer checks secret substring. Some model denominators are below the nominal template count; no ordinary-task utility score. |
| <https://arxiv.org/pdf/2603.12277v1> | Role-confusion study with attempted agent exfil and one upload example. | Appendix B.2 defines Figure 3 ASR as Gemini-judged *attempts*, regardless of upload success. Figure 15 displays one upload tool result with a paste URL; no aggregate accepted-send or receiver rate is established. Later v6 states the same attempt-based definition. |
| <https://arxiv.org/pdf/2603.12277v6> | Later version of Role Confusion, checked against the cited v1 outcome definition. | Appendix B.2 again defines success as attempted exfil regardless of upload outcome. This confirms the original seed's former "upload rate" reading was wrong. |
| <https://arxiv.org/pdf/2302.12173> | Foundational indirect prompt-injection threat model and synthetic agent cases. | Greshake et al., §§4.1-4.3 and §5.2: lower-trust web/email content can redirect an agent with read/send tools. Synthetic applications ignored unrelated queries and had no real external requests; Bing Chat demonstrations were separate. Do not treat its conceptual data-theft channel as verified outsider receipt. |
| <https://arxiv.org/pdf/2406.13352v3> | Stateful indirect-injection benchmark and negative case. | AgentDojo checks simulated environment state separately from task utility. A travel case requiring both unwanted booking and emailed data had zero full successes. |
| <https://arxiv.org/pdf/2403.02691v3> | Two-step read/send attack model. | InjecAgent's data-theft checker parses read and messaging tool calls. Its read response is simulated and no external recipient delivery is established. |
| <https://arxiv.org/pdf/2506.01055> | Disclosure-specific banking-agent study. | Its checker detects a synthetic detail in output or tool logs. Reported attack success is disclosure, not proof of accepted email delivery. |
| <https://arxiv.org/pdf/2407.12784> | Direct memory-write attacker power. | AgentPoison assumes partial memory/RAG write access and a retrieval trigger. Retrieval, generated action and environment effect are different reported metrics; no external exfil receipt. |
| <https://arxiv.org/pdf/2503.03704> | Query-only memory contamination. | MINJA relies on cross-user shared memory and save rules. Its success is later targeted reasoning in an answer, not an unauthorized transfer. |
| <https://arxiv.org/abs/2608.14876> | Repository layout as an injection variable. | Abstract only: reports effects of directory depth, modularity, placement and entry point. Exfil outcome and released receipt were not checked. |
| <https://arxiv.org/abs/2609.08371> | Agent capability boundaries as a comparison. | Abstract only: typed per-agent capabilities reduced injected effects in a small coding-repair study; not a general exfil rate. |
| <https://github.com/safety-research/SHADE-Arena/tree/357a429> | Hidden side-task baseline with a named-model saved trajectory. | Prior code audit found a synthetic-key send-email trajectory and simulated inbox scorer. The leak objective was assigned to the model. |
| <https://github.com/UKGovernmentBEIS/control-arena/tree/fa57942bcbf681d2a358f6c3f947087a55e3efbc> | Receiver-log scoring pattern. | Prior code audit found a BashArena scorer that checks a separate logging server for sensitive fixture strings. A fixed-policy test is not a model-positive trajectory. |
| <https://github.com/AI-secure/DecodingTrust-Agent/tree/5e0d7cc0c8f08da60af0d99594e9dddac2d3f91d> | Simulated mail with persisted state and named-model traces. | Prior code audit found a Gmail handler that persists sent mail in a tenant database and a GPT-5.4 positive synthetic trajectory. The judge checks sender mail, not a separate recipient readback. |
| <https://arxiv.org/pdf/2610.22987> | Persistent approval as a boundary between benign work and later unauthorized action. | From Approval to Abuse, §§2-4 and Appendices A.2/C: four coding-agent configurations and two-stage repository-context evaluation. A selected case reports controlled receiver receipt after user-approved broad permission; published 47/58 aggregate spans five goal types and is not an exfil rate. |
| <https://arxiv.org/pdf/2606.07131> | Third-party skill files as instruction and code surfaces. | MalSkillBench, §§3-4: generated skills were run in a Docker evaluation, but verifier can pass on IOC or judge evidence without a canary at a receiver. Targeted generation yield is not a model compromise rate. |
| <https://arxiv.org/pdf/2610.14488> | Containment and authorization negative control. | Names Are Not Objects, §§2 and 5-6: object-bound broker outperformed lexical allowlists on scripted probes. No LLM prompt-injection attempts or exfil success rates were tested. |
| <https://arxiv.org/pdf/2608.27092> | Framing of a secret as ordinary task metadata. | The Framing Gap, §§2-4 and 7: one-step mock `post_data` action can contain a synthetic token; no actual socket. A deployed ChatGPT probe with its synthetic secret resisted 48 valid attempts, without an outbound connector. |
| <https://arxiv.org/pdf/2602.22450> | Receiver request versus user-visible answer. | Silent Egress, §§5-6: local Qwen 2.5 7B and custom URL preview. Reported endpoint hits in 423/480 attacks are not verified full-secret leaks. Table 4's sharded Leak@3 is below Leak@1 despite an "any fragment in first k" definition, so those comparisons are internally inconsistent without a missing denominator change. |
| <https://arxiv.org/pdf/2610.01768> | Negative control for pre-encoded data in a URL. | The Innocent Courier, §§4-5: an agent follows a benign debugging link whose URL already contains a known secret. Real receiver traffic is reported, but this is not an agent retrieving and choosing to disclose a secret. |
| <https://arxiv.org/pdf/2509.10540> | Secondary route to EchoLeak literature. | Secondary analysis of Aim Labs' production disclosure. It is not independent primary outcome evidence; follow the original report. |
| <https://arxiv.org/pdf/2508.12175v1> | Calendar and inbox titles as lower-trust entry points on an assistant with browser access. | Invitation Is All You Need!, §5.5.3: paper reports browser requests containing six meeting titles and an email-subject example. Individual case denominators and platform-version portability are not established. |
| <https://arxiv.org/pdf/2606.24322> | Delayed memory-to-action authorization control. | Securing LLM-Agent Long-Term Memory, §§II and V-VI: synthetic harness reports consequential data-send actions after poisoned memory and 0% with an origin-bound gate. No external receiver validation; shared cross-agent memory is out of scope. |
| <https://github.com/yedidel/mem-inv-bench> | Released artifact for the memory authorization study. | `ACTION-CONTRACT.md` describes an in-memory ledger and no interactive user approval or production deployment. Useful for distinguishing an action-gate test from delivered exfil. |
| <https://arxiv.org/pdf/2609.39678> | Task-specific test for unnecessary permissions. | Aletheia, §§2-5: compares functional task completion with and without a requested permission. Its finding concerns excessive permission rules, not a received secret. |
| <https://arxiv.org/pdf/2605.18583> | Non-injected scope-creep baseline for coding agents. | Overeager Coding Agents, abstract only: benign tasks without explicit consent wording showed more out-of-scope actions across several harnesses. Exfil and receiver outcomes were not checked. |
| <https://arxiv.org/pdf/2605.01970> | Delayed inbox injection with later user data and simulated outbound mail. | Trojan Hippo Bench, §§3-4 and 7: one attacker-controlled email can persist through memory and later induce a send of synthetic PII. Outbox checks recipient and body, with semantic-judge fallback; no real Internet mail. |
| <https://github.com/debesheedas/trojan-hippo-benchmark/blob/main/src/benchmark/test_validators.py> | Outcome checker for Trojan Hippo Bench. | Validator reads simulated outbox JSON, checks recipient and exact or contained body data, then may accept semantic equivalence if string checks fail. This is stronger than answer-only scoring but weaker than independent external receipt. |
| <https://arxiv.org/pdf/2605.17986> | Live tool environments and side-effect checks for indirect injections. | LivePI, §4/Table 4 and Appendix A: 169 feasible cases across several surfaces/goals. Aggregate model rates are not exfil-specific; group chat enters as `user` in one OpenClaw setup, unlike ordinary tool-result data. |
| <https://github.com/leizhao7/livepi/tree/d48d3fa4949c587bef5de93a088fd9457b8544a6> | Released LivePI environment and email-side-effect verifier. | Code checks for a new message in a test recipient inbox, with recipient and task-keyword match. It does not require exact protected bytes; released artifacts are partial versus the full Table 4 matrix. |
| <https://www.aim.security/lp/aim-labs-echoleak-m365> | Original EchoLeak disclosure lead. | Site returned HTTP 403 to this team; primary screenshots, receiver receipts and denominator could not be checked. |
| <https://services.nvd.nist.gov/rest/json/cves/2.0?cveId=CVE-2025-32711> | Independent vulnerability index for EchoLeak. | NVD links the Aim Labs disclosure. A vulnerability record is not an agent exfil action trace. |
| <https://msrc.microsoft.com/update-guide/vulnerability/CVE-2025-32711> | Vendor advisory for the EchoLeak CVE. | Independent vulnerability record; the primary data-transfer sequence remains unverified here. |
| <https://sites.google.com/view/invitation-is-all-you-need> | Author page for the invitation paper. | Project page was accessible, but Saker found no published full trace/code. Paper figures and illustrative request path remain the checked evidence. |
| <https://arxiv.org/pdf/2607.20759> | Coding-issue artifact formats and checker-design caution. | IssueTrojanBench, §III/Table II: measured attempted installs and file artifacts across auto-accept coding runs. Its aggregate 66.5% is not a data-receiver or exfil rate. |
| <https://arxiv.org/pdf/2512.16962> | Retrieved-memory ranking and admission variables. | MemoryGraft, §§3 and 5: 23 of 48 retrieved records were poisoned for selected queries. This is a retrieval share, not a harmful action or exfil success rate. |
| <https://arxiv.org/pdf/2606.09935> | External contributor material in coding-agent CI workflows. | GitInject, §§3-5 and Appendix B: ephemeral GitHub repositories with live Actions and API state checks. | <https://github.com/ceferisbarov/GitInject/tree/644065205fc2972a3fe3c75e5bab5d81986fa152> | Released CI attack scenarios and exact publication checker. | One scenario checks GitHub PR comments for the expected runtime token, confirming repository-visible publication rather than a separate HTTP receiver. Do not copy example credentials from repository artifacts. |

| <https://arxiv.org/pdf/2610.28810> | Privileged organization-instruction plus connector disclosure. | Combining Long-Term Memory and LLMs Comes at a High Cost, §V: authors report prompts/usernames/timestamps written to attacker-controlled Drive by Claude Team, but attack required organization-owner instructions and connector setup. Not ordinary-user memory poisoning. |
| <https://github.com/PedroBarcha/Memory-injection> | Artifact for privileged connector/memory study. | Source located by Hayabusa; real platform artifact and failed ChatGPT URL-exfil reproductions are described in paper. Code and artifact were not independently run here. |
